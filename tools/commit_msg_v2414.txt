MundoDonghuaProvider v2 -> v3:
- El tab "Fm" (fmoon) ya no sirve un player clásico: bysekoze.com pasó a ser una
  SPA ("Byse Frontend") que consume una API propia con gate de Proof-of-Work y
  playback cifrado. El extractor StreamWish anterior devolvía 0 enlaces.
- Ingeniería inversa de la API verificada en vivo con los episodios de prueba
  (the-first-immortal-of-sword-art/1 y the-first-immortal-of-sword-art-2/1):
  1) POST /api/videos/{code}/embed/captcha -> {pow_nonce, pow_difficulty, pow_token}
  2) PoW: hallar N tal que el hash custom de "nonce:N" tenga >= dificultad bits
     en cero a la izquierda (dificultad 16 bits, solución típica ~15-30k intentos)
  3) POST /embed/captcha/verify {pow_token, solution} -> {status:"ok", token}
  4) POST /embed/playback {fingerprint} + X-Captcha-Token (el fingerprint solo
     necesita existir como objeto; no valida attestation)
     -> {playback:{algorithm, iv, payload, key_parts[], version}}
  5) key = b64url(key_parts[version-1]) + b64url(key_parts[30-version]);
     AES-256-GCM -> {sources:[{url, mime_type, label, height}]}
- La API valida el dominio del embed: la API rechazaba requests con
  Origin/Referer ajenos ("embedding from X is not allowed for this video");
  se envían Origin/Referer/X-Embed-* de mundodonghua.com en todas las llamadas.
- Nuevo objeto mdFmoonByseExtractor (port exacto del hash PoW del bundle JS,
  desempaquetado base64url de key_parts y descifrado AES-GCM con javax.crypto),
  cableado en mdHandleEmbed para bysekoze.com; filemoon.to sigue en StreamWish.
- E2E verificado en vivo: ambos episodios emiten master.m3u8 1080p válido
  (edge1-vienna-sprintcdn / edge1-madrid-sprintcdn, HTTP 200 #EXTM3U).
